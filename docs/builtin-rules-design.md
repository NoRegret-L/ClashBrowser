# 内置 Loyalsoldier 规则：开发规范

状态：2026-11-27 五轮 grilling 全部 24 项由用户确认。架构保持 Flutter + Mihomo，仅浏览器应用内代理，不使用系统 VPN/TUN/系统代理。分阶段验收；尚未实测的能力不得宣称安全。

| 决策 | 已确认行为 |
| --- | --- |
| Q1 | 默认白名单智能分流；国内直连，未匹配走选定代理，绝不失败回退直连。 |
| Q2 | 安装包内置本地 MRS 快照，无首次启动下载依赖。 |
| Q3 | 广告拦截默认开启、可关闭。 |
| Q4 | 默认允许局域网（不等于开放监听器）。 |
| Q5 | 用户规则优先，其后广告、私有网络、Apple/iCloud、Google/代理、国内、兜底；内部代理端口保护优先于用户规则。 |
| Q6 | 局域网允许 HTTP/HTTPS；公网仍仅 HTTPS；不允许公网页面任意跨域访问本地服务。 |
| Q7 | 发布内置快照，同时提供手动/自动更新。 |
| Q8 | 验证后原子替换，更新失败继续使用最近有效快照。 |
| Q9 | 智能分流、全局代理、严格自定义三模式；默认智能分流。 |
| Q10 | 私有 IPv4/IPv6、本地域名及本机回环允许主动访问；保护内部认证代理端口。 |
| Q11 | 全局代理保留广告拦截及局域网/回环直连例外；严格自定义按配置。 |
| Q12 | IP 规则使用 no-resolve，不为判定国内 IP 主动解析；已知 IP 再匹配。 |
| Q13 | GitHub Actions 用固定 Mihomo 转换器统一生成 MRS，三端共用。 |
| Q14 | 应用启动/恢复前台检查每日更新，代理就绪后通过所选节点下载；不申请后台常驻。 |
| Q15 | 独立策略管理页及浏览器快捷切换。 |
| Q16 | 安全重启应用新规则，先关闭原生渲染/连接再更换端点；不用未经验证的热重载。 |
| Q17 | 持久化模式、规则开关、自定义和最近有效规则；订阅凭据独立安全存储。 |
| Q18 | 展示 Mihomo 实际命中结果，不用 Flutter 模拟匹配，不开放外部控制器。 |

| Q20 | HTTPS、SHA-256、Ed25519、单调版本；内置公钥，CI 受保护签名私钥，防回滚。 |
| Q21 | 最新有效→最近有效→内置快照；均失败则禁止启动，不降级直连。 |
| Q22 | 独立规则流水线、校验过的 SDK 缓存、按变更增量编译。 |
| Q23 | 真实 HTTPS、路由优先级/模式、LAN/回环保护、损坏/签名/断更/回滚、三端编译及真机隔离门禁。 |
| Q24 | 分五阶段提交、测试、验收；正式发布前完成授权/源码审查。 |

## 实施阶段与不变量

1. 内置规则：固定上游 release revision 与许可证来源，Mihomo CLI 转换域名/IP MRS，统一资产与 SHA-256 清单；原生层仅构造固定本地 provider，不接受订阅 rule-providers、路径或 URL。默认 UI 智能分流，保留严格回归及临时模式选择和广告开关。加载失败禁止开放认证监听。原生配置仍保持 allow-lan=false、127.0.0.1、无 TUN/DNS 服务/控制器。此阶段尚不放宽 WebView 的 HTTPS/IP 限制，私有域名/保留 IP 先 REJECT，不声称已支持局域网或能防 DNS rebinding。
2. 策略管理：全局模式、策略页、持久化、原生命中信息，扩大自定义类型。安全重启时确保旧 WebView/连接销毁；不要依赖跨平台热更新。
3. 局域网：逐端验证 HTTP/HTTPS、本地域名/IPv4/IPv6/回环，明确受控跨域隔离及内部代理端口禁止访问。不能仅凭分流规则推断浏览器私网隔离；若平台不能满足，报告阻塞而非放宽默认。
4. 更新：使用独立规则 CI 每日构建，保护签名密钥；Ed25519 验证、单调版本持久化、代理下载、原子快照和回退。签名公钥/私钥尚未配置；第一阶段仅信任随应用打包的快照，绝不接收在线未签名数据。
5. 发布：覆盖全部测试，真实设备验证；双版本 JS 实验验证，签名安装包，GPL-3.0 权利及完整对应源码审查。

## 规则范围和依据

使用 [Loyalsoldier/clash-rules](https://github.com/Loyalsoldier/clash-rules) GPL-3.0 数据。采用 [Mihomo rule-provider](https://wiki.metacubex.one/config/rule-providers/) 原生 file/domain/ipcidr/MRS。白名单按上游含义，未知走代理。applications 是系统进程规则，不适用于浏览器；gfw/tld-not-cn 在白名单兜底下不改变代理结果，不重复加载；不依赖 GEOIP 自动下载，使用上游 cncidr/telegramcidr MRS。域名规则优先，IP 规则 no-resolve。快照来源、生成器、原始规则、许可证、哈希随构建产物保存。

根因：手工白名单使绝大多数正常网页/子资源 REJECT。归纳偏置：成熟域名集合及已知 IP 前缀作为明确的分类先验；匹配顺序决定路由，不用评分、阈值或经验权重。未知流量走选定代理；安全限制和数据有效性先于可用性。消融：相同节点/目标/认证下比较严格与智能，验证未知请求走代理、广告拒绝、用户覆盖和损坏失败关闭。性能以实际 MRS 大小及加载测试衡量，不预设涨幅。风险：直连规则可能改变实际出口，广告误拦截，数据陈旧，更新及私网隔离风险；应用内全局路由变化，系统网络配置保持不变。
