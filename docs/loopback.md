# Dedicated no-TUN loopback and HTTPS import

The native source is compiled into all three pinned wrappers, reusing Mihomo's executor and HTTP handler; it does not call their VPN lifecycle. The OS allocates a loopback IPv4 TCP port; each session gets a cryptographically random 256-bit password, not a fixed port or a heuristic. The handler has a dedicated authentication store and no listener outside loopback. Stop closes the owned listener and tracked client sockets and suspends the tunnel engine (not an OS tunnel). Native code reconstructs the projected configuration and allows only explicit suffix rules ending in REJECT. Runtime device behavior and outbound resource cleanup still require verification. No webview is enabled; authenticated proxy support must be established per platform before navigation.

HTTPS subscription import is explicit, user-triggered direct traffic, with normal platform TLS validation, no redirect, and bounded download size/time (resource safety limits, not routing hyperparameters). No token is logged or stored; imported nodes remain session-only. No HTTP, redirects, Base64 URI list, original rules/groups, proxy providers, automatic refresh, or persistent storage yet. Existing YAML field compatibility limits apply. Some common providers redirect and will require a separately reviewed redirect policy. The test suite checks URL validation, not a live subscription service.

Build gates: real authenticated HTTP routing, rejection, duplicate start, and shutdown tested on Linux against the Apple derivative; native cross-compilation and packaged apps on all three. Device runtime, WebView proxy authentication and absence of VPN/network leakage are not proven by these builds. CI includes local adapter source in SDK/app artifacts. Full license compliance remains a release gate.
